# 데스크톱 생산성 관리 앱 설계 명세서

## 1. 문서 목적

Windows에서 사용자의 실제 활성 앱 및 웹사이트 이용시간을 자동 측정하고, 생산성 분류·목표 관리·집중 세션·부드러운 개입을 제공하는 소규모 베타 제품의 설계를 정의한다. 제품은 로컬 우선으로 동작하며, 사용자가 로그인한 경우에만 선택적으로 클라우드 동기화를 수행한다.

이번 베타는 개인 생산성 사용자를 대상으로 한다. 향후 조직용 기능과 macOS·Android·iOS 지원을 추가할 수 있도록 경계를 분리하되, 현재 구현 범위에는 포함하지 않는다.

## 2. 목표 및 성공 기준

### 2.1 제품 목표

- 사용자가 별도 기록 없이 자신의 실제 활성시간을 파악할 수 있게 한다.
- 앱과 웹사이트를 생산적 또는 비생산적 활동으로 분류하고 사용자가 기준을 수정할 수 있게 한다.
- 생산시간 목표, 비생산시간 한도, 집중 세션을 한곳에서 관리한다.
- 강제 차단 없이 알림과 의식적 멈춤을 통해 자발적인 행동 전환을 돕는다.
- 인터넷이나 계정 없이 핵심 기능을 모두 사용할 수 있게 한다.
- 로그인한 사용자는 여러 Windows 기기에서 설정·목표·활동 요약을 동기화할 수 있게 한다.

### 2.2 베타 성공 기준

- 실제 활성시간 대비 일일 측정 오차가 ±5% 이내이다.
- 설정한 유휴 기준 도달 후 10초 이내에 활동 집계를 중지한다.
- 8시간 연속 실행 중 치명적 오류가 발생하지 않는다.
- 유휴 상태의 평균 CPU 사용률은 1% 이하, 메모리는 150MB 이하를 목표로 한다.
- 인터넷 연결 없이 측정·분류·목표·집중 세션·분석이 정상 동작한다.
- 동기화 재시도, 중복 제거, 설정 충돌 처리가 자동 검증된다.
- 페이지 본문, 키 입력, 화면 이미지가 수집·저장되지 않음을 검증한다.
- Windows 10 22H2와 Windows 11의 지원 중인 최신 버전에서 동작한다.

## 3. 범위

### 3.1 베타 포함 범위

- Windows 포그라운드 앱과 사용자 유휴 상태 감지
- Chrome·Edge 확장 프로그램을 통한 활성 탭의 도메인 측정
- 앱·도메인의 기본 생산성 분류와 사용자 수정
- 오늘의 생산시간 목표와 비생산시간 한도
- 집중·휴식 타이머
- 알림, 5~15초의 의식적 멈춤, 계속 사용 또는 활동 전환 선택
- 오늘 대시보드, 일·주간 분석, 활동 상세 타임라인
- 로컬 데이터 저장, 내보내기, 기간별 삭제, 전체 초기화
- 선택형 계정 로그인과 다중 Windows 기기 동기화
- 서명된 Windows 설치 파일, 자동 업데이트, 개인정보를 배제한 오류 진단

### 3.2 명시적 제외 범위

- 앱이나 웹사이트의 강제 차단
- 키 입력 내용, 화면 캡처, 문서 내용, 웹페이지 본문 수집
- 백그라운드에서 실행 중이지만 사용하지 않는 앱의 시간 집계
- 결제, 구독, 조직 관리자 화면, 직원 감시 기능
- macOS·Android·iOS 클라이언트 구현
- AI 기반 자동 분류
- 모바일 브라우저의 사이트별 정밀 추적

## 4. 핵심 원칙

1. **로컬 우선:** 로컬 SQLite를 원본 저장소로 사용하며 서버 장애가 핵심 기능에 영향을 주지 않는다.
2. **최소 수집:** 기능에 필요한 앱 식별자, 도메인, 시각, 분류 결과만 기록한다.
3. **사용자 통제:** 측정 일시정지, 제외 대상 설정, 삭제, 내보내기를 사용자가 직접 수행한다.
4. **비강제 개입:** 접근을 막지 않고 사용자가 자신의 행동을 인식하고 선택하게 한다.
5. **모듈 경계:** 수집, 분류, 정책, 저장, 동기화, 화면을 독립적으로 변경·시험할 수 있게 한다.
6. **플랫폼 확장:** 공통 데이터 모델과 정책 엔진은 유지하고 OS별 수집기만 교체할 수 있게 한다.

| 로컬 저장 | SQLite + SQLCipher | 활동 기록, 규칙, 목표, 설정, 동기화 큐 |

## 6. 논리 아키텍처

### 6.1 Windows 활동 수집기

- 현재 포그라운드 프로세스와 앱 식별자를 읽는다.
- 키보드·마우스의 마지막 입력 시각으로 유휴 상태를 판단한다.
- 화면 잠금, 절전, 로그아웃을 감지하면 즉시 세션을 종료한다.
- 창 제목은 분류를 위해 일시적으로 사용할 수 있으나 기본 설정에서는 저장하지 않는다.
- 사용자가 지정한 앱은 수집 단계에서 제외할 수 있다.

### 6.2 브라우저 확장

- Chrome과 Edge에서 현재 활성 창의 활성 탭만 보고한다.
- 기본적으로 정규화된 도메인만 전달하고 전체 URL, 제목, 페이지 본문은 전달하지 않는다.
- Native Messaging 연결이 끊기면 재연결을 시도하고, 그동안 데스크톱 앱은 브라우저 프로세스 사용으로만 기록한다.
- 차단 기능은 제공하지 않는다.

### 6.3 세션 정규화기

- OS 수집기와 확장 프로그램의 이벤트를 공통 `ActivitySession` 형식으로 변환한다.
- 짧게 연속된 동일 활동은 하나의 세션으로 병합한다.
- 유휴 시간과 측정 불가 구간은 생산성 계산에서 제외한다.
- 브라우저 앱 세션과 도메인 세션이 겹치면 도메인 세션을 우선하여 중복 집계를 방지한다.

### 6.4 분류·코칭 엔진

- 분류 우선순위는 사용자 규칙, 기본 규칙, 미분류 순이다.
- 분류 상태는 `productive`, `unproductive`, `neutral`, `unclassified`를 사용한다.
- 생산성 비율은 `생산적 활성시간 ÷ (생산적 활성시간 + 비생산적 활성시간)`으로 계산한다. 중립·미분류·유휴 시간은 분모에서 제외한다.
- 비생산 한도의 80% 도달 시 사전 알림을, 100% 도달 시 의식적 멈춤 화면을 표시한다.
- 의식적 멈춤 후 사용자는 계속 사용 또는 생산적 활동으로 전환을 선택한다. 어떤 선택도 접근을 차단하지 않는다.
- 알림 이후 계속 사용한 시간과 활동 전환 횟수를 회고 지표로 집계한다.

### 6.5 로컬 저장소

- 모든 쓰기는 로컬에서 먼저 완료한다.
- 상세 활동 기록은 기본 90일간 보관한다.
- 일·주간 집계는 사용자가 삭제할 때까지 보관한다.
- 사용자는 보관 기간을 변경하고 기간별 또는 전체 데이터를 삭제할 수 있다.
- 동기화 대상 변경은 별도 큐에 기록해 네트워크 장애와 앱 재시작에 견딘다.

### 6.6 동기화 서비스

- 로그인은 선택 사항이며 로그아웃 상태에서도 핵심 기능이 동일하게 작동한다.
- 기본 동기화 대상은 설정, 목표, 분류 규칙, 활동 요약이다.
- 상세 활동 기록 동기화는 사용자가 명시적으로 켠 경우에만 수행한다.
- 모든 전송은 TLS를 사용하고, 민감한 동기화 payload는 클라이언트에서 암호화한다.
- 사용자별 행 수준 보안 정책으로 다른 계정의 데이터 접근을 차단한다.
- 활동 기록은 불변 ID를 기준으로 합치고, 설정과 목표 충돌은 마지막 수정 시각을 적용한다.
- 삭제 작업은 tombstone으로 동기화하여 다른 기기에서 데이터가 되살아나지 않게 한다.

## 7. 데이터 모델

### 7.1 주요 엔터티

| 엔터티 | 핵심 필드 | 설명 |
|---|---|---|
| `ActivitySession` | id, device_id, source_type, app_id/domain, started_at, ended_at, active_seconds, classification | 실제 활성 활동 구간 |
| `ClassificationRule` | id, target_type, target_value, classification, source, updated_at | 기본 또는 사용자 분류 규칙 |
| `DailyGoal` | date/rule, productive_target, unproductive_limit, timezone | 일일 목표와 한도 |
| `FocusSession` | id, planned_seconds, active_seconds, break_seconds, status | 집중·휴식 세션 |
| `InterventionEvent` | id, trigger, shown_at, user_choice, followup_seconds | 알림과 사용자 반응 |
| `DailyAggregate` | date, productive_seconds, unproductive_seconds, neutral_seconds, goal_result | 일일 요약 |
| `Device` | id, user_id, device_platform, name, tracking_capabilities, last_seen_at | 플랫폼별 기기 정보 |
| `SyncOperation` | id, entity_type, entity_id, operation, revision, status | 로컬 동기화 큐 |

### 7.2 시간 처리

- 모든 원시 시각은 UTC로 저장하고 화면에서 사용자의 시간대로 변환한다.
- 일일 목표와 집계에는 적용 당시 시간대를 함께 저장한다.
- 시스템 시각이 역행하거나 급격히 변경되면 현재 세션을 종료하고 새 세션을 시작한다.
- 자정을 넘는 세션은 사용자의 현지 날짜 경계에서 분할한다.

## 8. 사용자 경험

### 8.1 최초 설정

1. Windows 앱 설치 및 자동 시작 여부 선택
2. 활동 측정 범위와 개인정보 보호 원칙 안내
3. Windows 활동 감지 권한과 동작 상태 확인
4. Chrome·Edge 확장 프로그램 설치 및 연결 확인
5. 기본 분류표 검토
6. 생산시간 목표, 비생산시간 한도, 집중·휴식 주기 설정
7. 선택적으로 계정 생성 및 동기화 활성화

### 8.2 기본 탐색 구조

- **오늘:** 오늘의 생산시간, 비생산시간, 목표 진척도, 다음 행동, 시간 분포
- **분석:** 일·주간 추세, 앱·사이트 분포, 목표 달성률, 전환 행동
- **활동 상세:** 시간순 활동 기록과 분류 수정
- **목표:** 일일 목표, 비생산 한도, 집중 세션 설정
- **분류:** 앱·도메인별 분류 검색·수정과 미분류 목록
- **동기화:** 로그인, 기기 목록, 최근 동기화 상태
- **설정:** 알림, 유휴 기준, 제외 대상, 보관 기간, 내보내기·삭제

### 8.3 대시보드 시각 체계

- 네이비: 기본 구조와 주요 탐색
- 녹색: 생산적 활동과 목표 달성
- 적색: 비생산적 활동과 한도 초과
- 보라색: 판단, 코칭, 다음 행동
- 파란색: 로컬 데이터 및 일반 정보
- 청록색: 계정과 클라우드 동기화
- 황색·주황색: 한도 접근과 주의 알림

기본 대시보드는 ‘오늘의 행동 중심’ 구조를 사용한다. 주간 분석은 별도 분석 탭에, 시간순 기록은 활동 상세 화면에 배치한다.

## 9. 오류 처리

| 상황 | 처리 원칙 |
|---|---|
| Windows 추적 실패 | 임의 추정하지 않고 해당 구간을 ‘측정 불가’로 표시 |
| 확장 연결 끊김 | 앱 측정은 유지하고 웹 활동은 브라우저 사용으로 집계 |
| 인터넷 연결 끊김 | 로컬 기능을 유지하고 재연결 후 동기화 재개 |
| 동기화 실패 | 로컬 원본을 보존하고 지수 백오프로 재시도 |
| 앱 비정상 종료 | 마지막 정상 heartbeat 시점까지만 세션 복구 |
| 중복 이벤트 | 기기 ID와 세션 ID를 기준으로 멱등 처리 |
| 절전·로그아웃·화면 잠금 | 진행 세션 즉시 종료 |
| 알림 실패 | 측정·저장과 분리하여 기록 손실 방지 |
| 권한 철회 | 측정을 중단하고 상태와 복구 방법을 명확히 안내 |

## 10. 보안 및 개인정보 보호

- 로컬 데이터베이스 암호화 키와 인증 토큰은 Windows Credential Manager에 저장한다.
- 데이터베이스, 로그, 오류 보고에 키 입력·페이지 본문·화면 이미지가 포함되지 않도록 금지 목록 테스트를 둔다.
- 오류 진단 전송은 기본 비활성화하고 사용자가 동의한 경우에만 익명 기술정보를 보낸다.
- Native Messaging은 허용된 확장 ID만 연결하고 메시지 스키마를 검증한다.
- 클라우드 API는 최소 권한과 사용자별 행 수준 보안을 적용한다.
- 계정 탈퇴 시 서버 데이터를 삭제하고 동기화 tombstone을 처리한다.
- 전체 데이터 삭제에는 명확한 확인 절차를 두되, 사용자의 요청을 불필요하게 지연시키지 않는다.

## 11. 시험 전략

### 11.1 단위 시험

- 세션 병합·분할, 유휴 시간 제외, 자정 경계, 시각 변경
- 규칙 우선순위와 생산성 비율 계산
- 목표 임계치와 알림 발생 조건
- 충돌 병합과 tombstone 처리

### 11.2 통합 시험

- Windows 수집기 → 정규화기 → SQLite 저장
- Chrome·Edge 확장 → Native Messaging → 세션 변환
- 오프라인 변경 → 재연결 → 클라우드 동기화
- 앱 재시작 후 진행 세션 복구

### 11.3 사용자 흐름 시험

- 최초 설치부터 첫 활동 기록까지
- 분류 수정 후 과거·현재 집계 반영
- 목표와 집중 세션 생성·완료
- 알림 후 계속 사용 또는 활동 전환 선택
- 데이터 내보내기, 기간별 삭제, 전체 초기화

### 11.4 비기능 시험

- 8시간 이상 장시간 실행
- CPU·메모리·배터리 영향 측정
- 대량 활동 기록에서 대시보드 응답시간 확인
- Windows 10·11과 Chrome·Edge 조합별 호환성
- 네트워크 단절, 토큰 만료, 서버 오류 복구
- 민감정보 비수집과 로그 마스킹 검증

## 12. 배포 및 운영

- 소규모 초대형 베타로 배포한다.
- Windows 코드 서명된 설치 파일을 제공한다.
- 자동 업데이트는 서명 검증 후 적용하며 실패 시 기존 버전을 유지한다.
- 개인정보를 포함하지 않는 상태 진단 화면을 제공해 사용자가 지원 요청 시 직접 내보낼 수 있게 한다.
- 베타 지표는 설치 성공률, 일일 측정 성공률, 확장 연결률, 동기화 성공률, 치명적 오류율을 중심으로 본다.

## 13. 플랫폼 확장 로드맵

1. Windows 소규모 베타를 안정화한다.
2. macOS용 활성 앱·유휴 상태 수집기를 추가하고 공통 UI와 정책 엔진을 재사용한다.
3. Android는 사용정보 접근 권한 기반 앱 사용시간 수집기를 별도 구현한다.
4. iOS는 FamilyControls·DeviceActivity의 권한, 개인정보 보호, 보고서 제약을 기술검증한 뒤 범위를 확정한다.

모바일 앱은 이번 베타에 포함하지 않는다. 공통 엔터티에 `device_platform`, `device_id`, `tracking_capabilities`를 포함해 플랫폼별 측정 능력 차이를 표현한다.

## 14. 승인된 주요 결정

- Windows 우선, 향후 macOS 및 모바일 확장
- 개인용으로 시작하고 향후 조직용으로 확장
- Tauri 2 + React·TypeScript + Rust 채택
- Chrome·Edge 확장 프로그램으로 도메인 측정
- 기본 분류표 제공 및 사용자 수정
- 실제 활성시간만 측정
- 생산시간 목표, 비생산시간 한도, 집중 세션 모두 제공
- 로컬 우선과 선택형 계정·클라우드 동기화
- 강제 차단 제외
- 행동 중심 대시보드를 기본 화면으로 채택
- 모바일은 로드맵에만 반영하고 Windows 베타 범위를 유지
